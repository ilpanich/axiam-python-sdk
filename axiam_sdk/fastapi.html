axiam_sdk.fastapi

FastAPI Depends(...) dependency-injection integration (D-09, CONTRACT.md §10/§11).

Verifies an AXIAM access token LOCALLY (no per-request round-trip to the AXIAM server on a JWKS cache hit) via axiam_sdk._jwks.JwksVerifier and returns the authenticated identity (user_id, tenant_id, roles) for injection into a FastAPI route via Depends(...).

This module is a dependency-only integration (D-09) — there is deliberately no ASGI-middleware variant. It is imported ONLY as axiam_sdk.fastapi (never from the top-level axiam_sdk/__init__.py, see Anti-Pattern/T-19-22) so that pure-REST/gRPC/AMQP consumers of axiam-sdk are never forced to install fastapi.

Security-critical invariant — the CONTRACT.md §10.1 minimum local-verification set: this dependency turns a token into an identity without asking the server, so it MUST apply every §10.1 rule, and it does so through the single ~axiam_sdk._jwks.JwksVerifier.verify_access_token() entry point — EdDSA-pinned signature before key lookup, required numeric exp, nbf when present, required tenant_id asserted against the configured tenant, and iss/aud when the verifier is configured with an expected value, all under a bounded, named clock skew. The signature-only primitive (verify_signature_only_unchecked) is deliberately never called here: a guard that checks the signature and stops is not a weaker guard, it is not a guard.

Security-critical invariant — cross-tenant token replay defense (T-19-19, §10.1 rule 4): the AXIAM JWKS is organization-wide, not tenant-scoped, so a token that is signature-valid may still belong to a different tenant. tenant_id is required and asserted against configured_tenant before any claim is trusted further — mirrors the Go SDK's middleware/nethttp.go lines 78-95.

Security-critical invariant — expiry (T-19-20, §10.1 rule 2): exp is REQUIRED. A token carrying no exp at all is a permanent credential and is rejected, not treated as "no expiry constraint" (the SEC-080 defect); so is a non-numeric exp.

Security-critical invariant — no token leakage (T-19-21): no raw token value is ever included in any HTTPException detail.

CSRF (cookie double-submit, CONTRACT.md §3): a request authenticated via the axiam_access COOKIE is not CSRF-immune the way a Authorization: Bearer header request is — a cross-site attacker cannot set arbitrary request headers, but a same-site cookie is attached to cross-site requests automatically by the browser. For any cookie-sourced credential on a state-changing method (anything other than GET/HEAD/OPTIONS), this dependency additionally requires the X-CSRF-Token request header to be present and equal (constant-time) to the axiam_csrf cookie value, rejecting with 403 on mismatch/absence. This mirrors, locally, the same double-submit check the AXIAM server performs on its own endpoints (§3) — see also the Java SDK's .../AxiamAuthenticationFilter.java for the same pattern applied to the Spring integration.

CONTRACT.md §11 — declarative authorization helpers: require_access() and require_role() are an additive per-endpoint authorization layer built strictly on top of the authentication pipeline above (shared via the internal _authenticate() helper both require_authenticated_user() and require_access() compose with — the §10 verification path, JWKS, tenant check, CSRF, is never re-implemented or bypassed). require_access resolves a target resource UUID from the request (§11.3 precedence: resource_id literal, then resource_param path parameter, then a resolver callback), then calls ~axiam_sdk.AsyncAxiamClient's check_access(...) with subject_id set to the authenticated caller's user_id (§11.2) — never this SDK client's own, typically service-account, identity. Error mapping (§11.2, §2): unauthenticated -> 401 authentication_failed; denied or AuthzError -> 403 authorization_denied; missing/unparseable resource id -> 400 invalid_request; AuthError/NetworkError while calling the authz endpoint (the SDK client could not obtain a decision) -> fail closed with 503 authz_unavailable, per §11.2.5's "never allow on transport failure" rule. No decision caching (§11.2.6) — every call is a fresh authz-endpoint round-trip. Deny/error paths never log or echo the token (§11.2.8). require_role is a local, no-round-trip check against the already- verified identity's roles (§11.2.9) — it is NOT a substitute for require_access's authoritative, resource-level server check.

140def _extract_token(request: Request) -> _Credential:
141    """Extract the bearer token from ``Authorization: Bearer <token>``,
142    falling back to the ``axiam_access`` session cookie.
143
144    Ported 1:1 from ``the Go SDK's middleware/nethttp.go``'s ``extractToken``
145    (lines 109-125): Bearer header first, cookie fallback second, standardized
146    401 with no token value on failure — this exact ordering is a Shared
147    Pattern (19-PATTERNS.md) also used by the Django middleware.
148    """
149    header = request.headers.get("authorization")
150    if header:
151        scheme, _, credentials = header.strip().partition(" ")
152        if scheme.lower() == "bearer" and credentials.strip():
153            return _Credential(credentials.strip(), from_cookie=False)
154        raise HTTPException(
155            status_code=_AUTH_FAILED_STATUS, detail="missing authentication credentials"
156        )
157
158    cookie = request.cookies.get("axiam_access")
159    if cookie:
160        return _Credential(cookie, from_cookie=True)
161
162    raise HTTPException(
163        status_code=_AUTH_FAILED_STATUS, detail="missing authentication credentials"
164    )

167def _assert_csrf_valid(request: Request) -> None:
168    """Cookie double-submit check (CONTRACT.md §3): the ``X-CSRF-Token``
169    request header must be present and equal, constant-time, to the
170    ``axiam_csrf`` cookie value. Raises ``HTTPException`` 403 on
171    mismatch/absence.
172
173    Only called for cookie-sourced credentials on state-changing methods
174    (see ``_dependency``) — a Bearer-header request is CSRF-immune by
175    construction, since a cross-site attacker cannot set arbitrary request
176    headers.
177    """
178    header = request.headers.get(_CSRF_HEADER_NAME)
179    cookie = request.cookies.get(_CSRF_COOKIE_NAME)
180    if not header or not cookie or not hmac.compare_digest(header, cookie):
181        raise HTTPException(status_code=_CSRF_FAILED_STATUS, detail="CSRF validation failed")

184async def _authenticate(
185    request: Request, verifier: JwksVerifier, configured_tenant: str
186) -> AxiamUser:
187    """The shared extract/CSRF/§10.1-verify authentication pipeline
188    (CONTRACT.md §10) underlying both :func:`require_authenticated_user` and
189    :func:`require_access` (CONTRACT.md §11.2.1: the declarative
190    authorization helper MUST run strictly after, and never duplicate or
191    bypass, this same verification path).
192
193    1. Extracts the token (Authorization Bearer, else ``axiam_access`` cookie).
194    2. When the credential is cookie-sourced AND the request method is
195       state-changing (not GET/HEAD/OPTIONS), enforces the CSRF
196       double-submit check (CONTRACT.md §3) before verification proceeds —
197       raises ``HTTPException`` 403 on failure.
198    3. Applies the COMPLETE CONTRACT.md §10.1 minimum local-verification set
199       via ``verifier.verify_access_token(...)``: EdDSA-pinned signature
200       (before key lookup), required numeric ``exp``, ``nbf`` when present,
201       required ``tenant_id`` asserted against ``configured_tenant``, and
202       ``iss``/``aud`` when the verifier was configured with an expected
203       value — all under the verifier's bounded, named clock skew. The
204       signature-only primitive is never used here.
205    4. Returns :class:`AxiamUser` on success; raises ``HTTPException`` 401 on
206       any authentication failure, never including the raw token value.
207    """
208    credential = _extract_token(request)
209
210    if credential.from_cookie and request.method.upper() not in _SAFE_METHODS:
211        _assert_csrf_valid(request)
212
213    token = credential.value
214
215    try:
216        # CONTRACT.md §10.1: a single call applying every rule. Any rule
217        # violation — including a token with no ``exp`` at all, which the
218        # previous ``exp``-if-present check accepted (SEC-080) — raises and
219        # maps to the standardized 401 below, never a 500 and never a
220        # silent accept.
221        claims = verifier.verify_access_token(token, expected_tenant_id=configured_tenant)
222    except Exception as exc:
223        raise HTTPException(
224            status_code=_AUTH_FAILED_STATUS, detail="invalid or expired token"
225        ) from exc
226
227    tenant_id = claims["tenant_id"]
228
229    # WR-02: ``dict.get("scope", "")`` returns ``None`` (not ``""``) when
230    # the claim is PRESENT with an explicit JSON ``null`` value, and
231    # ``list(None)`` raises TypeError — which would propagate AFTER the
232    # verify() try/except above and surface as an unhandled 500 for an
233    # otherwise signature-valid token. ``claims.get("scope") or ""`` maps
234    # both absent AND null scope to empty roles, matching how an absent
235    # scope is already handled (CONTRACT.md §10: malformed claims must
236    # still degrade to a standardized 401, never a 500).
237    roles_claim = claims.get("scope") or ""
238    roles = roles_claim.split() if isinstance(roles_claim, str) else list(roles_claim)
239
240    subject = claims.get("sub")
241    if not subject:
242        raise HTTPException(status_code=_AUTH_FAILED_STATUS, detail="invalid or expired token")
243
244    return AxiamUser(user_id=subject, tenant_id=tenant_id, roles=roles)

247def require_authenticated_user(
248    verifier: JwksVerifier, configured_tenant: str
249) -> Callable[[Request], Awaitable[AxiamUser]]:
250    """Factory returning a ``Depends(...)``-compatible async dependency
251    (mirrors the Go middleware's ``Middleware(verifier, configuredTenant,
252    opts...)`` factory pattern, D-09).
253
254    Usage::
255
256        @app.get("/me")
257        async def me(user: AxiamUser = Depends(require_authenticated_user(verifier, "acme"))):
258            ...
259
260    CONTRACT.md §10.1 rules 5-7 are configured on the ``verifier``, not here,
261    so every guard built from the same verifier shares one policy::
262
263        verifier = JwksVerifier(
264            base_url,
265            expected_issuer="https://axiam.example.com",   # optional, unset by default
266            expected_audience=RECOMMENDED_RESOURCE_SERVER_AUDIENCE,  # optional
267            clock_skew_seconds=DEFAULT_CLOCK_SKEW_SECONDS,  # bounded, named
268        )
269
270    The returned dependency delegates to :func:`_authenticate` for the full
271    extract/CSRF/§10.1-verify pipeline — see that function's docstring
272    for the exact steps. Returns :class:`AxiamUser` on success; raises
273    ``HTTPException`` 401 on any authentication failure, never including the
274    raw token value.
275    """
276
277    async def _dependency(request: Request) -> AxiamUser:
278        """The actual ``Depends(...)``-injected coroutine — delegates
279        entirely to :func:`_authenticate` (see :func:`require_authenticated_user`'s
280        docstring for the pipeline it runs)."""
281        return await _authenticate(request, verifier, configured_tenant)
282
283    return _dependency

286def _resolve_resource_id(
287    request: Request,
288    *,
289    resource_id: str | None,
290    resource_param: str | None,
291    resolver: Callable[[Request], str] | None,
292) -> str:
293    """Resolve and validate the target resource UUID per CONTRACT.md
294    §11.2.3's precedence order: a literal ``resource_id``, else the
295    ``resource_param`` path parameter, else the ``resolver`` callback.
296
297    A missing or unparseable resource value is a programming error surfaced
298    as ``HTTPException`` 400 (§11.2.5) — never a silent allow, never a
299    nil/empty-UUID fallback.
300    """
301    raw: object
302    if resource_id is not None:
303        raw = resource_id
304    elif resource_param is not None:
305        raw = request.path_params.get(resource_param)
306        if raw is None:
307            raise HTTPException(
308                status_code=_INVALID_REQUEST_STATUS,
309                detail={
310                    "error": "invalid_request",
311                    "message": f"missing path parameter {resource_param!r}",
312                },
313            )
314    else:
315        assert resolver is not None  # enforced by require_access at construction time
316        try:
317            raw = resolver(request)
318        except Exception as exc:
319            raise HTTPException(
320                status_code=_INVALID_REQUEST_STATUS,
321                detail={"error": "invalid_request", "message": "resource resolver failed"},
322            ) from exc
323
324    try:
325        uuid.UUID(str(raw))
326    except (ValueError, AttributeError, TypeError) as exc:
327        raise HTTPException(
328            status_code=_INVALID_REQUEST_STATUS,
329            detail={"error": "invalid_request", "message": "resource id is not a valid UUID"},
330        ) from exc
331    return str(raw)

334def require_access(
335    verifier: JwksVerifier,
336    configured_tenant: str,
337    client: AsyncAxiamClient,
338    action: str,
339    *,
340    resource_param: str | None = None,
341    resource_id: str | None = None,
342    resolver: Callable[[Request], str] | None = None,
343    scope: str | None = None,
344    uma_challenge: UmaChallenger | None = None,
345) -> Callable[[Request], Awaitable[AxiamUser]]:
346    """Factory returning a ``Depends(...)``-compatible async dependency that
347    requires an AXIAM authorization check for ``action`` on a resource
348    resolved from the request (CONTRACT.md §11).
349
350    Composes with, and runs strictly after, the same authentication pipeline
351    :func:`require_authenticated_user` uses (:func:`_authenticate` — never a
352    separate/duplicated token-verification path, §11.2.1).
353
354    Usage::
355
356        @app.get("/docs/{doc_id}")
357        async def get_doc(
358            doc_id: str,
359            user: AxiamUser = Depends(
360                require_access(verifier, "acme", client, "read", resource_param="doc_id")
361            ),
362        ):
363            ...
364
365    Exactly one of ``resource_id`` (a literal UUID, for singleton resources),
366    ``resource_param`` (a path parameter name), or ``resolver`` (a
367    ``request -> str`` callback for anything else — body fields, headers,
368    composite lookups) must be supplied (§11.2.3); this is validated eagerly
369    at factory-construction time, not per-request.
370
371    The returned dependency:
372    1. Authenticates the request via :func:`_authenticate` (401 on failure).
373    2. Resolves and validates the resource UUID (400 on a missing/unparseable
374       value, §11.2.3).
375    3. Calls ``client.check_access(action, resource_id, scope=scope,
376       subject_id=<authenticated user_id>)`` — ``subject_id`` is always the
377       *request's* authenticated caller, never this client's own (often
378       service-account) identity (§11.2.2).
379    4. Denied (``allowed=False`` or an ``AuthzError`` from the server, e.g. the
380       client lacks ``authz:check_as``) -> ``HTTPException`` 403
381       ``authorization_denied``.
382    5. A transport failure (``AuthError``/``NetworkError`` — the SDK could not
383       obtain a decision at all) -> **fail closed** with ``HTTPException`` 503
384       ``authz_unavailable`` (§11.2.5) — never allow, never retry beyond the
385       client's own bounded single-flight refresh.
386    6. On success, returns the same :class:`AxiamUser` so the handler keeps
387       the caller's identity (roles etc.) without a second lookup.
388
389    No decision caching (§11.2.6): every call performs a fresh
390    ``check_access`` round-trip. Deny/error paths never log or echo the raw
391    token (§11.2.8).
392
393    Pass ``uma_challenge`` (a :class:`~axiam_sdk.UmaChallenger`) and a denial
394    also carries ``WWW-Authenticate: UMA`` with a freshly minted ticket for the
395    action just refused (§20.3) — so a UMA-aware client learns where to obtain
396    authority instead of only being told no. The 403 body is unchanged, so a
397    client that does not speak UMA sees exactly what it saw before. It is
398    opt-in, and minting failures do not escalate the denial; see
399    :class:`~axiam_sdk.UmaChallenger` for why both matter.
400    """
401    resource_sources = [
402        source for source in (resource_id, resource_param, resolver) if source is not None
403    ]
404    if len(resource_sources) != 1:
405        raise ValueError(
406            "require_access requires exactly one of resource_id, resource_param, or resolver"
407        )
408
409    async def _dependency(request: Request) -> AxiamUser:
410        """The actual ``Depends(...)``-injected coroutine — authenticate,
411        resolve the resource, then perform the authorization check (see
412        :func:`require_access`'s docstring for the full pipeline)."""
413        user = await _authenticate(request, verifier, configured_tenant)
414        target_resource_id = _resolve_resource_id(
415            request,
416            resource_id=resource_id,
417            resource_param=resource_param,
418            resolver=resolver,
419        )
420
421        try:
422            result = await client.check_access(
423                action, target_resource_id, scope=scope, subject_id=user.user_id
424            )
425        except AuthzError as exc:
426            raise await _denied(action, target_resource_id, uma_challenge) from exc
427        except (AuthError, NetworkError) as exc:
428            # §11.2.5: fail closed — a transport failure while calling the
429            # authz endpoint is "couldn't decide", never a silent allow.
430            raise HTTPException(
431                status_code=_AUTHZ_UNAVAILABLE_STATUS,
432                detail={
433                    "error": "authz_unavailable",
434                    "message": "authorization service unavailable",
435                },
436            ) from exc
437
438        if not result.allowed:
439            raise await _denied(action, target_resource_id, uma_challenge)
440        return user
441
442    return _dependency

445async def _denied(action: str, resource_id: str, challenger: UmaChallenger | None) -> HTTPException:
446    """Build the 403, minting a §20.3 challenge when one was configured.
447
448    Only ever reached on a path that has already decided to refuse, so minting
449    cannot change the outcome — at worst it fails and the caller gets the plain
450    403 they would have got anyway.
451    """
452    detail = {
453        "error": "authorization_denied",
454        "message": f"caller lacks permission for action {action!r}",
455    }
456    if challenger is None:
457        return HTTPException(status_code=_AUTHZ_DENIED_STATUS, detail=detail)
458
459    try:
460        # §20.2: the UMA scope is the AXIAM *action*, which is what makes the
461        # ticket ask for exactly the authority this check just refused — and
462        # what keeps a deny rule vetoing the resulting RPT the same way it
463        # vetoed the check.
464        ticket = await challenger.client.uma_request_ticket(
465            challenger.pat,
466            [RequestedPermission(resource_id=resource_id, resource_scopes=[action])],
467        )
468    except Exception:  # noqa: BLE001 - see UmaChallenger's "failure is not escalation"
469        # Deliberately broad and deliberately silent: any failure to mint leaves
470        # the denial exactly as it was. Not logged either, because a Protection
471        # API failure message can echo a credential and §11.2.8 keeps those out
472        # of this path.
473        return HTTPException(status_code=_AUTHZ_DENIED_STATUS, detail=detail)
474
475    return HTTPException(
476        status_code=_AUTHZ_DENIED_STATUS,
477        detail=detail,
478        # Additive: the body above is the unchanged §11.2.5 shape.
479        headers={
480            "WWW-Authenticate": uma_challenge_header(challenger.realm, challenger.as_uri, ticket)
481        },
482    )

485def require_role(
486    verifier: JwksVerifier, configured_tenant: str, *roles: str
487) -> Callable[[Request], Awaitable[AxiamUser]]:
488    """Factory returning a ``Depends(...)``-compatible async dependency that
489    requires the authenticated identity's verified ``roles`` to contain at
490    least one of ``roles`` (CONTRACT.md §11).
491
492    A **local** check only — reads the claims already verified by
493    :func:`_authenticate`; it never calls the AXIAM server. Cheaper but
494    coarser than :func:`require_access`, and documented (§11.2.9) as NOT a
495    substitute for the authoritative, resource-level check: role names are
496    tenant-defined and callers should still gate any resource-specific
497    action behind :func:`require_access`.
498
499    Usage::
500
501        @app.delete("/admin/reset")
502        async def reset(user: AxiamUser = Depends(require_role(verifier, "acme", "admin"))):
503            ...
504    """
505
506    async def _dependency(request: Request) -> AxiamUser:
507        """The actual ``Depends(...)``-injected coroutine — authenticate,
508        then check the verified identity's roles locally (see
509        :func:`require_role`'s docstring)."""
510        user = await _authenticate(request, verifier, configured_tenant)
511        if not any(role in user.roles for role in roles):
512            raise HTTPException(
513                status_code=_AUTHZ_DENIED_STATUS,
514                detail={
515                    "error": "authorization_denied",
516                    "message": "caller lacks a required role",
517                },
518            )
519        return user
520
521    return _dependency

543def oidc_login_router(
544    client: AsyncAxiamClient,
545    *,
546    redirect_uri: str,
547    store: OidcStateStore | None = None,
548    scope: str | list[str] | None = None,
549    tenant_id: str | None = None,
550    login_path: str = "/login",
551    callback_path: str = "/callback",
552    success_redirect: str | None = None,
553    on_success: Callable[[OidcTokenSet, OidcStateEntry], Awaitable[None]] | None = None,
554) -> APIRouter:
555    """Build a two-route "Login with AXIAM" :class:`~fastapi.APIRouter`
556    (CONTRACT.md §12): ``GET {login_path}`` starts the authorization-code +
557    PKCE flow and redirects the browser to AXIAM's authorization endpoint;
558    ``GET {callback_path}`` completes it.
559
560    Delegates entirely to the shared §12 core already on ``client``
561    (``oidc_discover``/``oidc_begin``/``oidc_exchange``, CONTRACT.md §12.3
562    rule 1's stateless-by-default operations) and to the existing session
563    cookie machinery in ``_session.py`` — this factory adds no token
564    handling of its own beyond parking the ``state``/``nonce``/
565    ``code_verifier`` triple in ``store`` between the two requests (the
566    SDK itself is stateless; a redirect flow's two HTTP requests need
567    somewhere to keep that triple, since only ``state`` survives the round
568    trip through the IdP).
569
570    Args:
571        client: The :class:`~axiam_sdk.AsyncAxiamClient` driving the flow —
572            already configured with ``client_id``/``client_secret``.
573        redirect_uri: The relying party's own callback URL — must be the
574            public URL of ``callback_path`` and is replayed verbatim on the
575            token exchange.
576        store: Where in-flight login state is parked. Defaults to a fresh
577            :class:`~axiam_sdk.MemoryOidcStateStore` (single-process only —
578            supply a shared store for a multi-instance deployment).
579        scope: Requested scope; ``openid`` is added automatically when
580            absent (§12.1 rule 4).
581        tenant_id: Tenant UUID for the token endpoint's required
582            ``tenant_id`` query parameter (CONTRACT.md §12.3 rule 4).
583            Defaults to the client's own resolved tenant context (e.g. from
584            a prior ``login()``) when omitted.
585        login_path: The login-redirect route path, relative to the router.
586        callback_path: The callback route path, relative to the router.
587        success_redirect: Where to send the browser after a successful
588            login. Falls back to the ``return_to`` query parameter captured
589            at login time, then to a JSON summary.
590        on_success: Called with the validated token set and the consumed
591            state entry once the exchange succeeds — the hook where an
592            application establishes its OWN session (sign a cookie, write a
593            session row, ...). The SDK deliberately does not do this: what a
594            session means is the application's decision.
595
596    Returns:
597        An :class:`~fastapi.APIRouter` with the two routes, ready to
598        ``app.include_router(...)``.
599    """
600    state_store: OidcStateStore = store if store is not None else MemoryOidcStateStore()
601    router = APIRouter()
602
603    @router.get(login_path)
604    async def login(return_to: str | None = None) -> RedirectResponse:
605        """Step 1 — build the authorization request, park its state, and
606        redirect the browser (CONTRACT.md §12.1 ``oidc_begin``)."""
607        try:
608            configuration = await client.oidc_discover()
609            request = await client.oidc_begin(
610                configuration=configuration, redirect_uri=redirect_uri, scope=scope
611            )
612        except (AuthError, NetworkError, httpx.HTTPError) as exc:
613            # A login route that cannot reach AXIAM must fail closed with
614            # 503 rather than redirect the browser somewhere half-built.
615            # `httpx.HTTPError` covers a raw transport failure (connection
616            # refused, timeout, DNS, TLS) that this SDK's transport layer
617            # does not itself wrap into `NetworkError`.
618            raise HTTPException(
619                status_code=_OIDC_UNAVAILABLE_STATUS,
620                detail=_oidc_unavailable_detail("could not start the OIDC login flow"),
621            ) from exc
622
623        state_store.save(
624            OidcStateEntry(
625                state=request.state,
626                nonce=request.nonce,
627                code_verifier=request.code_verifier,
628                redirect_uri=redirect_uri,
629                return_to=return_to,
630            )
631        )
632        return RedirectResponse(url=request.url, status_code=302)
633
634    @router.get(callback_path)
635    async def callback(
636        state: str | None = None,
637        code: str | None = None,
638        error: str | None = None,
639        error_description: str | None = None,
640    ) -> Response:
641        """Step 2 — validate the callback, consume the stored state,
642        exchange the code, and respond (CONTRACT.md §12.1 ``oidc_exchange``).
643
644        Failure mapping (port-brief-addendum item 19): IdP returned
645        ``error=...`` -> 401; ``state``/``code`` missing -> 400; ``state``
646        unknown/expired/already-used -> 401; any §12.4 ID-token failure or
647        ``OAuthProtocolError`` -> 401; a transport failure -> 503.
648        """
649        if error:
650            raise HTTPException(
651                status_code=_OIDC_AUTH_FAILED_STATUS,
652                detail=_oidc_auth_failed_detail(
653                    f"{error}: {error_description}" if error_description else error
654                ),
655            )
656        if not state or not code:
657            raise HTTPException(
658                status_code=_OIDC_INVALID_REQUEST_STATUS,
659                detail={
660                    "error": "invalid_request",
661                    "message": "callback is missing the state or code query parameter",
662                },
663            )
664
665        # Single-use consume (§12.3 rule 1): a replayed callback finds nothing.
666        entry = state_store.consume(state)
667        if entry is None:
668            raise HTTPException(
669                status_code=_OIDC_AUTH_FAILED_STATUS,
670                detail=_oidc_auth_failed_detail("unknown, expired, or already-used login state"),
671            )
672
673        try:
674            tokens = await client.oidc_exchange(
675                code=code,
676                code_verifier=entry.code_verifier,
677                redirect_uri=entry.redirect_uri,
678                nonce=entry.nonce,
679                tenant_id=tenant_id,
680            )
681        except (NetworkError, httpx.HTTPError) as exc:
682            raise HTTPException(
683                status_code=_OIDC_UNAVAILABLE_STATUS,
684                detail=_oidc_unavailable_detail("the AXIAM token endpoint is unreachable"),
685            ) from exc
686        except AuthError as exc:
687            # AuthError (including OAuthProtocolError and every §12.4 reason
688            # code): a login that cannot be proven is a failed login.
689            raise HTTPException(
690                status_code=_OIDC_AUTH_FAILED_STATUS,
691                detail=_oidc_auth_failed_detail(exc.message),
692            ) from exc
693
694        if on_success is not None:
695            await on_success(tokens, entry)
696
697        destination = success_redirect or entry.return_to
698        if destination:
699            return RedirectResponse(url=destination, status_code=302)
700
701        body: dict[str, object] = {"authenticated": True, "expires_in": tokens.expires_in}
702        if tokens.id_claims is not None:
703            body["sub"] = tokens.id_claims.sub
704        return JSONResponse(body)
705
706    return router

248    async def _authz_post_async(
249        self, path: str, body: dict[str, Any], *, operation: str
250    ) -> dict[str, Any]:
251        """POST an authz request body to *path* under the §16 retry policy.
252
253        The call is a ``POST`` but changes no server state, so it is
254        retry-eligible: §16.2's test is "changes no server state", NOT "is a
255        GET". Gating on the verb would exclude the single most important
256        operation this policy covers.
257
258        The §9.3 refresh-then-retry-once on a 401 is a *different* mechanism and
259        stays inside one §16 attempt: a 401 means the token expired, which
260        refreshing fixes, and neither backing off nor counting it against the
261        transport-failure budget would make sense.
262        """
263        return await retry_async(
264            lambda attempt: self._authz_post_async_once(path, body, operation, attempt),
265            operation=operation,
266            enabled=self._retry_enabled,
267            telemetry=self._telemetry,
268        )

270    async def _authz_post_async_once(
271        self, path: str, body: dict[str, Any], operation: str, attempt: int
272    ) -> dict[str, Any]:
273        """One §16 attempt, with its §19 request pair."""
274        request = self._session.async_client.build_request("POST", path, json=body)
275        with self._telemetry.request(operation, "POST", path, attempt) as span:
276            response = await self._session._send_async(request)
277
278            if response.status_code == httpx.codes.UNAUTHORIZED:
279                response = await self._retry_after_refresh_async(request)
280
281            span.status = response.status_code
282            if response.status_code < 200 or response.status_code >= 300:
283                raise error_from_http_status(
284                    response.status_code, "authz check failed", response=response
285                )
286            span.outcome = "success"
287            result: dict[str, Any] = response.json()

264    def verify_access_token(self, token: str, *, expected_tenant_id: str | None) -> dict[str, Any]:

266        set to ``token`` and return its claims. This is the documented guard
267        entry point; every SDK route guard and middleware goes through it.
268
269        The seven rules, in order:
270
271        1. ``alg`` pinned to ``EdDSA`` and checked BEFORE any keyset lookup,
272           so ``alg: none`` and HS-family confusion are rejected without ever
273           consulting a key.
274        2. ``exp`` is REQUIRED and must be a JSON number. An absent ``exp``
275           is a permanent credential, never "no expiry constraint"; a
276           numeric-string ``exp`` (which PyJWT would silently coerce) is a
277           wrong-typed claim and is rejected too.

281           the JWKS trust anchor is organization-wide, so signature validity
282           alone does not bound a token to a tenant.

284           ``expected_issuer``.

286           ``expected_audience``.

288           leeway (default :data:`DEFAULT_CLOCK_SKEW_SECONDS`).

291        or of the wrong JSON type causes rejection.

295            expected_tenant_id: The tenant this deployment serves. ``None`` or
296                empty is a configuration error and fails closed (rule 4).
297

300

303                callers map to HTTP 401 (CONTRACT.md §2/§10).
304        """

307            # nothing to assert the token against, which is a rejection, not

317            raise AuthError(f"unexpected alg {header.get('alg')!r}: only EdDSA is accepted")

325        # rather than left to defaults. `require` is what closes the SEC-080
326        # gap; PyJWT's own `Options` docstring states it outright: "Some
327        # claims, such as exp ... will only be verified if present ... make
328        # sure to include them in the require param".
329        required = ["sub", "exp", "tenant_id"]

331            required.append("iss")

333            required.append("aud")

339            # token outright when no `audience=` argument is supplied.

347                signing_key.key,

362            # letting it surface as an unhandled 500 in a caller's guard.

366        # so a string "9999999999" passes its own check; §10.1 requires the
367        # claim to be a JSON number, and a bool is not one either.
368        self._assert_numeric_claim(claims, "exp", required=True)

510                # an empty/malformed keyset response (e.g. a rotation
511                # window where the new key has not yet propagated).

513                # (unknown kid) and PyJWKSetError (empty/invalid keyset) —
514                # both failure modes warrant the same forced-refetch
515                # response below.
516                pass
517
518            now = time.monotonic()
519            if (
520                self._last_forced_refetch is not None
521                and now - self._last_forced_refetch < _FORCED_REFETCH_MIN_INTERVAL_SECONDS
522            ):

524                # recently (while we waited for the lock, or just before
525                # us) — surface whatever the current cache yields rather
526                # than hammering the endpoint again.
527                return self._client.get_signing_key_from_jwt(token)

529            # Force exactly one rate-limited refetch, then retry once. A
530            # second failure propagates to the caller.

The seven rules, in order:

  1. alg pinned to EdDSA and checked BEFORE any keyset lookup, so alg: none and HS-family confusion are rejected without ever consulting a key.
  2. exp is REQUIRED and must be a JSON number. An absent exp is a permanent credential, never "no expiry constraint"; a numeric-string exp (which PyJWT would silently coerce) is a wrong-typed claim and is rejected too.
