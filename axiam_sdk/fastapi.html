axiam_sdk.fastapi

FastAPI Depends(...) dependency-injection integration (D-09, CONTRACT.md §10/§11).

Verifies an AXIAM access token LOCALLY (no per-request round-trip to the AXIAM server on a JWKS cache hit) via axiam_sdk._jwks.JwksVerifier and returns the authenticated identity (user_id, tenant_id, roles) for injection into a FastAPI route via Depends(...).

This module is a dependency-only integration (D-09) — there is deliberately no ASGI-middleware variant. It is imported ONLY as axiam_sdk.fastapi (never from the top-level axiam_sdk/__init__.py, see Anti-Pattern/T-19-22) so that pure-REST/gRPC/AMQP consumers of axiam-sdk are never forced to install fastapi.

Security-critical invariant — cross-tenant token replay defense (T-19-19): the AXIAM JWKS is organization-wide, not tenant-scoped, so a token that is signature-valid may still belong to a different tenant. This dependency enforces claims["tenant_id"] == configured_tenant BEFORE any claim is trusted further — mirrors the Go SDK's middleware/nethttp.go lines 78-95.

Security-critical invariant — expiry (T-19-20): JwksVerifier.verify() checks the signature only, not exp (documented on that class). This dependency independently rejects an expired-but-signature-valid token.

Security-critical invariant — no token leakage (T-19-21): no raw token value is ever included in any HTTPException detail.

CSRF (cookie double-submit, CONTRACT.md §3): a request authenticated via the axiam_access COOKIE is not CSRF-immune the way a Authorization: Bearer header request is — a cross-site attacker cannot set arbitrary request headers, but a same-site cookie is attached to cross-site requests automatically by the browser. For any cookie-sourced credential on a state-changing method (anything other than GET/HEAD/OPTIONS), this dependency additionally requires the X-CSRF-Token request header to be present and equal (constant-time) to the axiam_csrf cookie value, rejecting with 403 on mismatch/absence. This mirrors, locally, the same double-submit check the AXIAM server performs on its own endpoints (§3) — see also the Java SDK's .../AxiamAuthenticationFilter.java for the same pattern applied to the Spring integration.

CONTRACT.md §11 — declarative authorization helpers: require_access() and require_role() are an additive per-endpoint authorization layer built strictly on top of the authentication pipeline above (shared via the internal _authenticate() helper both require_authenticated_user() and require_access() compose with — the §10 verification path, JWKS, tenant check, CSRF, is never re-implemented or bypassed). require_access resolves a target resource UUID from the request (§11.3 precedence: resource_id literal, then resource_param path parameter, then a resolver callback), then calls ~axiam_sdk.AsyncAxiamClient's check_access(...) with subject_id set to the authenticated caller's user_id (§11.2) — never this SDK client's own, typically service-account, identity. Error mapping (§11.2, §2): unauthenticated -> 401 authentication_failed; denied or AuthzError -> 403 authorization_denied; missing/unparseable resource id -> 400 invalid_request; AuthError/NetworkError while calling the authz endpoint (the SDK client could not obtain a decision) -> fail closed with 503 authz_unavailable, per §11.2.5's "never allow on transport failure" rule. No decision caching (§11.2.6) — every call is a fresh authz-endpoint round-trip. Deny/error paths never log or echo the token (§11.2.8). require_role is a local, no-round-trip check against the already- verified identity's roles (§11.2.9) — it is NOT a substitute for require_access's authoritative, resource-level server check.

117class _Credential:
118    """A verified-candidate token plus whether it was sourced from the
119    ``axiam_access`` cookie (as opposed to the ``Authorization`` header) —
120    needed to decide whether the CSRF double-submit check applies."""

126def _extract_token(request: Request) -> _Credential:
127    """Extract the bearer token from ``Authorization: Bearer <token>``,
128    falling back to the ``axiam_access`` session cookie.
129
130    Ported 1:1 from ``the Go SDK's middleware/nethttp.go``'s ``extractToken``
131    (lines 109-125): Bearer header first, cookie fallback second, standardized
132    401 with no token value on failure — this exact ordering is a Shared
133    Pattern (19-PATTERNS.md) also used by the Django middleware.
134    """
135    header = request.headers.get("authorization")
136    if header:
137        scheme, _, credentials = header.strip().partition(" ")
138        if scheme.lower() == "bearer" and credentials.strip():
139            return _Credential(credentials.strip(), from_cookie=False)
140        raise HTTPException(
141            status_code=_AUTH_FAILED_STATUS, detail="missing authentication credentials"
142        )
143
144    cookie = request.cookies.get("axiam_access")
145    if cookie:
146        return _Credential(cookie, from_cookie=True)
147
148    raise HTTPException(
149        status_code=_AUTH_FAILED_STATUS, detail="missing authentication credentials"
150    )

153def _assert_csrf_valid(request: Request) -> None:
154    """Cookie double-submit check (CONTRACT.md §3): the ``X-CSRF-Token``
155    request header must be present and equal, constant-time, to the
156    ``axiam_csrf`` cookie value. Raises ``HTTPException`` 403 on
157    mismatch/absence.
158
159    Only called for cookie-sourced credentials on state-changing methods
160    (see ``_dependency``) — a Bearer-header request is CSRF-immune by
161    construction, since a cross-site attacker cannot set arbitrary request
162    headers.
163    """
164    header = request.headers.get(_CSRF_HEADER_NAME)
165    cookie = request.cookies.get(_CSRF_COOKIE_NAME)
166    if not header or not cookie or not hmac.compare_digest(header, cookie):
167        raise HTTPException(status_code=_CSRF_FAILED_STATUS, detail="CSRF validation failed")

170async def _authenticate(
171    request: Request, verifier: JwksVerifier, configured_tenant: str
172) -> AxiamUser:
173    """The shared extract/CSRF/verify/exp/tenant authentication pipeline
174    (CONTRACT.md §10) underlying both :func:`require_authenticated_user` and
175    :func:`require_access` (CONTRACT.md §11.2.1: the declarative
176    authorization helper MUST run strictly after, and never duplicate or
177    bypass, this same verification path).
178
179    1. Extracts the token (Authorization Bearer, else ``axiam_access`` cookie).
180    2. When the credential is cookie-sourced AND the request method is
181       state-changing (not GET/HEAD/OPTIONS), enforces the CSRF
182       double-submit check (CONTRACT.md §3) before verification proceeds —
183       raises ``HTTPException`` 403 on failure.
184    3. Verifies it locally via ``verifier.verify()`` (signature + ``sub`` only).
185    4. Independently checks ``exp`` — the verifier does not (T-19-20).
186    5. Enforces ``claims["tenant_id"] == configured_tenant`` BEFORE trusting
187       any claim further (cross-tenant replay defense, T-19-19).
188    6. Returns :class:`AxiamUser` on success; raises ``HTTPException`` 401 on
189       any authentication failure, never including the raw token value.
190    """
191    credential = _extract_token(request)
192
193    if credential.from_cookie and request.method.upper() not in _SAFE_METHODS:
194        _assert_csrf_valid(request)
195
196    token = credential.value
197
198    try:
199        claims = verifier.verify(token)
200        # SDK-11: coerce ``exp`` to float INSIDE the verify try/except so a
201        # signature-valid token carrying a non-numeric ``exp`` (e.g. a
202        # string) maps to the normal invalid-token -> 401 path rather than
203        # a ValueError/TypeError propagating as an unhandled 500. Preserves
204        # the "malformed token -> 401" invariant (CONTRACT.md §10).
205        exp = claims.get("exp")
206        exp_ts = float(exp) if exp is not None else None
207    except Exception as exc:
208        raise HTTPException(
209            status_code=_AUTH_FAILED_STATUS, detail="invalid or expired token"
210        ) from exc
211
212    if exp_ts is not None and time.time() >= exp_ts:
213        raise HTTPException(status_code=_AUTH_FAILED_STATUS, detail="invalid or expired token")
214
215    # Cross-tenant replay defense (T-19-19): the JWKS is organization-wide,
216    # not tenant-scoped, so a signature-valid token may belong to a
217    # different tenant. MUST be enforced before any claim is trusted
218    # further (mirrors nethttp.go lines 78-95).
219    tenant_id = claims.get("tenant_id")
220    if not tenant_id or tenant_id != configured_tenant:
221        raise HTTPException(
222            status_code=_AUTH_FAILED_STATUS,
223            detail="token tenant_id does not match the configured tenant",
224        )
225
226    # WR-02: ``dict.get("scope", "")`` returns ``None`` (not ``""``) when
227    # the claim is PRESENT with an explicit JSON ``null`` value, and
228    # ``list(None)`` raises TypeError — which would propagate AFTER the
229    # verify() try/except above and surface as an unhandled 500 for an
230    # otherwise signature-valid token. ``claims.get("scope") or ""`` maps
231    # both absent AND null scope to empty roles, matching how an absent
232    # scope is already handled (CONTRACT.md §10: malformed claims must
233    # still degrade to a standardized 401, never a 500).
234    roles_claim = claims.get("scope") or ""
235    roles = roles_claim.split() if isinstance(roles_claim, str) else list(roles_claim)
236
237    subject = claims.get("sub")
238    if not subject:
239        raise HTTPException(status_code=_AUTH_FAILED_STATUS, detail="invalid or expired token")
240
241    return AxiamUser(user_id=subject, tenant_id=tenant_id, roles=roles)

273def _resolve_resource_id(
274    request: Request,
275    *,
276    resource_id: str | None,
277    resource_param: str | None,
278    resolver: Callable[[Request], str] | None,
279) -> str:
280    """Resolve and validate the target resource UUID per CONTRACT.md
281    §11.2.3's precedence order: a literal ``resource_id``, else the
282    ``resource_param`` path parameter, else the ``resolver`` callback.
283
284    A missing or unparseable resource value is a programming error surfaced
285    as ``HTTPException`` 400 (§11.2.5) — never a silent allow, never a
286    nil/empty-UUID fallback.
287    """
288    raw: object
289    if resource_id is not None:
290        raw = resource_id
291    elif resource_param is not None:
292        raw = request.path_params.get(resource_param)
293        if raw is None:
294            raise HTTPException(
295                status_code=_INVALID_REQUEST_STATUS,
296                detail={
297                    "error": "invalid_request",
298                    "message": f"missing path parameter {resource_param!r}",
299                },
300            )
301    else:
302        assert resolver is not None  # enforced by require_access at construction time
303        try:
304            raw = resolver(request)
305        except Exception as exc:
306            raise HTTPException(
307                status_code=_INVALID_REQUEST_STATUS,
308                detail={"error": "invalid_request", "message": "resource resolver failed"},
309            ) from exc
310
311    try:
312        uuid.UUID(str(raw))
313    except (ValueError, AttributeError, TypeError) as exc:
314        raise HTTPException(
315            status_code=_INVALID_REQUEST_STATUS,
316            detail={"error": "invalid_request", "message": "resource id is not a valid UUID"},
317        ) from exc
318    return str(raw)

321def require_access(
322    verifier: JwksVerifier,
323    configured_tenant: str,
324    client: AsyncAxiamClient,
325    action: str,
326    *,
327    resource_param: str | None = None,
328    resource_id: str | None = None,
329    resolver: Callable[[Request], str] | None = None,
330    scope: str | None = None,
331) -> Callable[[Request], Awaitable[AxiamUser]]:
332    """Factory returning a ``Depends(...)``-compatible async dependency that
333    requires an AXIAM authorization check for ``action`` on a resource
334    resolved from the request (CONTRACT.md §11).
335
336    Composes with, and runs strictly after, the same authentication pipeline
337    :func:`require_authenticated_user` uses (:func:`_authenticate` — never a
338    separate/duplicated token-verification path, §11.2.1).
339
340    Usage::
341
342        @app.get("/docs/{doc_id}")
343        async def get_doc(
344            doc_id: str,
345            user: AxiamUser = Depends(
346                require_access(verifier, "acme", client, "read", resource_param="doc_id")
347            ),
348        ):
349            ...
350
351    Exactly one of ``resource_id`` (a literal UUID, for singleton resources),
352    ``resource_param`` (a path parameter name), or ``resolver`` (a
353    ``request -> str`` callback for anything else — body fields, headers,
354    composite lookups) must be supplied (§11.2.3); this is validated eagerly
355    at factory-construction time, not per-request.
356
357    The returned dependency:
358    1. Authenticates the request via :func:`_authenticate` (401 on failure).
359    2. Resolves and validates the resource UUID (400 on a missing/unparseable
360       value, §11.2.3).
361    3. Calls ``client.check_access(action, resource_id, scope=scope,
362       subject_id=<authenticated user_id>)`` — ``subject_id`` is always the
363       *request's* authenticated caller, never this client's own (often
364       service-account) identity (§11.2.2).
365    4. Denied (``allowed=False`` or an ``AuthzError`` from the server, e.g. the
366       client lacks ``authz:check_as``) -> ``HTTPException`` 403
367       ``authorization_denied``.
368    5. A transport failure (``AuthError``/``NetworkError`` — the SDK could not
369       obtain a decision at all) -> **fail closed** with ``HTTPException`` 503
370       ``authz_unavailable`` (§11.2.5) — never allow, never retry beyond the
371       client's own bounded single-flight refresh.
372    6. On success, returns the same :class:`AxiamUser` so the handler keeps
373       the caller's identity (roles etc.) without a second lookup.
374
375    No decision caching (§11.2.6): every call performs a fresh
376    ``check_access`` round-trip. Deny/error paths never log or echo the raw
377    token (§11.2.8).
378    """
379    resource_sources = [
380        source for source in (resource_id, resource_param, resolver) if source is not None
381    ]
382    if len(resource_sources) != 1:
383        raise ValueError(
384            "require_access requires exactly one of resource_id, resource_param, or resolver"
385        )
386
387    async def _dependency(request: Request) -> AxiamUser:
388        """The actual ``Depends(...)``-injected coroutine — authenticate,
389        resolve the resource, then perform the authorization check (see
390        :func:`require_access`'s docstring for the full pipeline)."""
391        user = await _authenticate(request, verifier, configured_tenant)
392        target_resource_id = _resolve_resource_id(
393            request,
394            resource_id=resource_id,
395            resource_param=resource_param,
396            resolver=resolver,
397        )
398
399        try:
400            result = await client.check_access(
401                action, target_resource_id, scope=scope, subject_id=user.user_id
402            )
403        except AuthzError as exc:
404            raise HTTPException(
405                status_code=_AUTHZ_DENIED_STATUS,
406                detail={
407                    "error": "authorization_denied",
408                    "message": f"caller lacks permission for action {action!r}",
409                },
410            ) from exc
411        except (AuthError, NetworkError) as exc:
412            # §11.2.5: fail closed — a transport failure while calling the
413            # authz endpoint is "couldn't decide", never a silent allow.
414            raise HTTPException(
415                status_code=_AUTHZ_UNAVAILABLE_STATUS,
416                detail={
417                    "error": "authz_unavailable",
418                    "message": "authorization service unavailable",
419                },
420            ) from exc
421
422        if not result.allowed:
423            raise HTTPException(
424                status_code=_AUTHZ_DENIED_STATUS,
425                detail={
426                    "error": "authorization_denied",
427                    "message": f"caller lacks permission for action {action!r}",
428                },
429            )
430        return user
431
432    return _dependency

435def require_role(
436    verifier: JwksVerifier, configured_tenant: str, *roles: str
437) -> Callable[[Request], Awaitable[AxiamUser]]:
438    """Factory returning a ``Depends(...)``-compatible async dependency that
439    requires the authenticated identity's verified ``roles`` to contain at
440    least one of ``roles`` (CONTRACT.md §11).
441
442    A **local** check only — reads the claims already verified by
443    :func:`_authenticate`; it never calls the AXIAM server. Cheaper but
444    coarser than :func:`require_access`, and documented (§11.2.9) as NOT a
445    substitute for the authoritative, resource-level check: role names are
446    tenant-defined and callers should still gate any resource-specific
447    action behind :func:`require_access`.
448
449    Usage::
450
451        @app.delete("/admin/reset")
452        async def reset(user: AxiamUser = Depends(require_role(verifier, "acme", "admin"))):
453            ...
454    """
455
456    async def _dependency(request: Request) -> AxiamUser:
457        """The actual ``Depends(...)``-injected coroutine — authenticate,
458        then check the verified identity's roles locally (see
459        :func:`require_role`'s docstring)."""
460        user = await _authenticate(request, verifier, configured_tenant)
461        if not any(role in user.roles for role in roles):
462            raise HTTPException(
463                status_code=_AUTHZ_DENIED_STATUS,
464                detail={
465                    "error": "authorization_denied",
466                    "message": "caller lacks a required role",
467                },
468            )
469        return user
470
471    return _dependency

493def oidc_login_router(
494    client: AsyncAxiamClient,
495    *,
496    redirect_uri: str,
497    store: OidcStateStore | None = None,
498    scope: str | list[str] | None = None,
499    tenant_id: str | None = None,
500    login_path: str = "/login",
501    callback_path: str = "/callback",
502    success_redirect: str | None = None,
503    on_success: Callable[[OidcTokenSet, OidcStateEntry], Awaitable[None]] | None = None,
504) -> APIRouter:
505    """Build a two-route "Login with AXIAM" :class:`~fastapi.APIRouter`
506    (CONTRACT.md §12): ``GET {login_path}`` starts the authorization-code +
507    PKCE flow and redirects the browser to AXIAM's authorization endpoint;
508    ``GET {callback_path}`` completes it.
509
510    Delegates entirely to the shared §12 core already on ``client``
511    (``oidc_discover``/``oidc_begin``/``oidc_exchange``, CONTRACT.md §12.3
512    rule 1's stateless-by-default operations) and to the existing session
513    cookie machinery in ``_session.py`` — this factory adds no token
514    handling of its own beyond parking the ``state``/``nonce``/
515    ``code_verifier`` triple in ``store`` between the two requests (the
516    SDK itself is stateless; a redirect flow's two HTTP requests need
517    somewhere to keep that triple, since only ``state`` survives the round
518    trip through the IdP).
519
520    Args:
521        client: The :class:`~axiam_sdk.AsyncAxiamClient` driving the flow —
522            already configured with ``client_id``/``client_secret``.
523        redirect_uri: The relying party's own callback URL — must be the
524            public URL of ``callback_path`` and is replayed verbatim on the
525            token exchange.
526        store: Where in-flight login state is parked. Defaults to a fresh
527            :class:`~axiam_sdk.MemoryOidcStateStore` (single-process only —
528            supply a shared store for a multi-instance deployment).
529        scope: Requested scope; ``openid`` is added automatically when
530            absent (§12.1 rule 4).
531        tenant_id: Tenant UUID for the token endpoint's required
532            ``tenant_id`` query parameter (CONTRACT.md §12.3 rule 4).
533            Defaults to the client's own resolved tenant context (e.g. from
534            a prior ``login()``) when omitted.
535        login_path: The login-redirect route path, relative to the router.
536        callback_path: The callback route path, relative to the router.
537        success_redirect: Where to send the browser after a successful
538            login. Falls back to the ``return_to`` query parameter captured
539            at login time, then to a JSON summary.
540        on_success: Called with the validated token set and the consumed
541            state entry once the exchange succeeds — the hook where an
542            application establishes its OWN session (sign a cookie, write a
543            session row, ...). The SDK deliberately does not do this: what a
544            session means is the application's decision.
545
546    Returns:
547        An :class:`~fastapi.APIRouter` with the two routes, ready to
548        ``app.include_router(...)``.
549    """
550    state_store: OidcStateStore = store if store is not None else MemoryOidcStateStore()
551    router = APIRouter()
552
553    @router.get(login_path)
554    async def login(return_to: str | None = None) -> RedirectResponse:
555        """Step 1 — build the authorization request, park its state, and
556        redirect the browser (CONTRACT.md §12.1 ``oidc_begin``)."""
557        try:
558            configuration = await client.oidc_discover()
559            request = await client.oidc_begin(
560                configuration=configuration, redirect_uri=redirect_uri, scope=scope
561            )
562        except (AuthError, NetworkError, httpx.HTTPError) as exc:
563            # A login route that cannot reach AXIAM must fail closed with
564            # 503 rather than redirect the browser somewhere half-built.
565            # `httpx.HTTPError` covers a raw transport failure (connection
566            # refused, timeout, DNS, TLS) that this SDK's transport layer
567            # does not itself wrap into `NetworkError`.
568            raise HTTPException(
569                status_code=_OIDC_UNAVAILABLE_STATUS,
570                detail=_oidc_unavailable_detail("could not start the OIDC login flow"),
571            ) from exc
572
573        state_store.save(
574            OidcStateEntry(
575                state=request.state,
576                nonce=request.nonce,
577                code_verifier=request.code_verifier,
578                redirect_uri=redirect_uri,
579                return_to=return_to,
580            )
581        )
582        return RedirectResponse(url=request.url, status_code=302)
583
584    @router.get(callback_path)
585    async def callback(
586        state: str | None = None,
587        code: str | None = None,
588        error: str | None = None,
589        error_description: str | None = None,
590    ) -> Response:
591        """Step 2 — validate the callback, consume the stored state,
592        exchange the code, and respond (CONTRACT.md §12.1 ``oidc_exchange``).
593
594        Failure mapping (port-brief-addendum item 19): IdP returned
595        ``error=...`` -> 401; ``state``/``code`` missing -> 400; ``state``
596        unknown/expired/already-used -> 401; any §12.4 ID-token failure or
597        ``OAuthProtocolError`` -> 401; a transport failure -> 503.
598        """
599        if error:
600            raise HTTPException(
601                status_code=_OIDC_AUTH_FAILED_STATUS,
602                detail=_oidc_auth_failed_detail(
603                    f"{error}: {error_description}" if error_description else error
604                ),
605            )
606        if not state or not code:
607            raise HTTPException(
608                status_code=_OIDC_INVALID_REQUEST_STATUS,
609                detail={
610                    "error": "invalid_request",
611                    "message": "callback is missing the state or code query parameter",
612                },
613            )
614
615        # Single-use consume (§12.3 rule 1): a replayed callback finds nothing.
616        entry = state_store.consume(state)
617        if entry is None:
618            raise HTTPException(
619                status_code=_OIDC_AUTH_FAILED_STATUS,
620                detail=_oidc_auth_failed_detail("unknown, expired, or already-used login state"),
621            )
622
623        try:
624            tokens = await client.oidc_exchange(
625                code=code,
626                code_verifier=entry.code_verifier,
627                redirect_uri=entry.redirect_uri,
628                nonce=entry.nonce,
629                tenant_id=tenant_id,
630            )
631        except (NetworkError, httpx.HTTPError) as exc:
632            raise HTTPException(
633                status_code=_OIDC_UNAVAILABLE_STATUS,
634                detail=_oidc_unavailable_detail("the AXIAM token endpoint is unreachable"),
635            ) from exc
636        except AuthError as exc:
637            # AuthError (including OAuthProtocolError and every §12.4 reason
638            # code): a login that cannot be proven is a failed login.
639            raise HTTPException(
640                status_code=_OIDC_AUTH_FAILED_STATUS,
641                detail=_oidc_auth_failed_detail(exc.message),
642            ) from exc
643
644        if on_success is not None:
645            await on_success(tokens, entry)
646
647        destination = success_redirect or entry.return_to
648        if destination:
649            return RedirectResponse(url=destination, status_code=302)
650
651        body: dict[str, object] = {"authenticated": True, "expires_in": tokens.expires_in}
652        if tokens.id_claims is not None:
653            body["sub"] = tokens.id_claims.sub
654        return JSONResponse(body)
655
656    return router

298        self,
299        *,
300        refresh_token: SecretStr | str,
301        scope: str | None = None,
302        tenant_id: str | None = None,
303        configuration: OidcConfiguration | None = None,
304    ) -> OidcTokenSet:
305        """``POST /oauth2/token`` with ``grant_type=refresh_token``
306        (CONTRACT.md §12.1) — refresh an ``OidcTokenSet``.
307
308        A **distinct operation** from :meth:`refresh`, which drives the
309        cookie/opaque-token session path at ``POST /api/v1/auth/refresh``
310        (§12.1 "``oidc_refresh`` vs ``refresh``") — the two are never
311        merged, aliased, or made to fall back to one another. Concurrent
312        ``oidc_refresh`` calls collapse into exactly one wire call, and the
313        selected caller's wire call additionally runs inside the same §9
314        single-flight guard the cookie-session :meth:`refresh` uses, so an
315        ``oidc_refresh`` and a concurrent cookie-session refresh can never
316        interleave.
317        """
318
319        async def do_refresh() -> OidcTokenSet:
320            """Perform the actual ``refresh_token`` grant call; run inside
321            :meth:`~axiam_sdk.token.refresh_guard.RefreshGuard.run_exclusive_async`
322            by ``under_guard``, and de-duplicated across concurrent callers
323            by the single-flight coalescer below."""
324            config = configuration or await self.oidc_discover()
325            form = self._refresh_form(refresh_token=refresh_token, scope=scope)
326            url = self._token_endpoint_url(config, tenant_id)
327            request = self._session.async_client.build_request("POST", url, data=form)
328            response = await self._session._send_async(request)
329            # No nonce: rule 6 does not apply to a refresh-issued ID token.
330            return self._handle_token_response(response, config, None)
331
332        async def under_guard() -> OidcTokenSet:
333            """Run ``do_refresh`` inside the shared §9 refresh-guard lock,
334            so it can never interleave with a concurrent cookie-session
335            :meth:`refresh` call."""
336            token_set: OidcTokenSet = await self._session.refresh_guard.run_exclusive_async(
337                do_refresh
338            )
339            return token_set
340
341        result: OidcTokenSet = await self._oidc_refresh_single_flight_async.run(under_guard)
342        return result
